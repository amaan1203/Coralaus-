# coralaus Architecture & Implementation Guide

This document outlines the architecture and implementation strategy, an automated Agentic workflow designed to solve the "Reproducibility Crisis" in research. 

It leverages **Coral** for data retrieval (acting as the "Muscle" to fetch real-world Dockerfiles and codebase states via SQL) and an **LLM Agent** (acting as the "Brain") to synthesize working, modernized environments based on the HyDE + FLARE pattern.

---

## 1. Core Architecture Overview

The system abandons hardcoded dictionaries and generic LLM hallucination in favor of a **Crowd-Sourced, Agentic RAG Pipeline**. 

### The HyDE + FLARE Workflow
* **HyDE (Hypothetical Document Embeddings):** The Agent generates a "flawed" draft Dockerfile based on the `requirements.txt` if available. It extracts structural keywords from this draft to search GitHub (via Coral) for *real*, highly-rated Dockerfiles that solve similar dependency trees.
* **FLARE (Forward-Looking Active REtrieval):** While synthesizing the final Dockerfile, the Agent pauses if uncertain (e.g., "What is the exact wheel URL for torch 1.7.1 on cu101?"). It actively queries Coral (e.g., searching GitHub issues) to resolve the uncertainty before continuing generation.

### Component Map
1. **Frontend UI:** User uploads Research Paper (PDF/JSON) + `requirements.txt`.
2. **LLM Agent (Python/LangChain/Groq):** The orchestration layer executing the HyDE + FLARE logic.
3. **Coral MCP Server (Local):** Executes global GitHub searches, reads file trees, and fetches raw code contents using a unified SQL interface.

## 2. Implementation Pipeline

### Step 1: HyDE Draft Generation
**Goal:** Generate a structural starting point to use as a search query.

1.  **Agent Action:** The LLM is prompted to draft a Dockerfile strictly based on the uploaded `requirements.txt`. 
    * *Note: This draft is expected to be factually incorrect regarding base images, but structurally relevant.*
2.  **Keyword Extraction:** The Agent extracts the core system dependencies and framework tags from its draft (e.g., `FROM nvidia/cuda`, `libgl1`, `torchvision`).

### Step 2: Coral Reconnaissance (The SQL Retrieval)
**Goal:** Find real-world solutions that match the HyDE keywords.

1.  **Agent Action (MCP Client):** The Agent sends a dynamic SQL query to the Coral MCP Server to find repositories.
    ```sql
    -- Example Coral SQL Query generated by the Agent
    SELECT owner, repo 
    FROM github.search_code 
    WHERE query = 'FROM nvidia/cuda AND libgl1 filename:Dockerfile' 
    LIMIT 3;
    ```
2.  **Fetch Content:** The Agent uses Coral to download the actual Dockerfiles from the top 3 resulting repositories.
    ```sql
    SELECT repo, content 
    FROM github.contents 
    WHERE repo IN ('repo_A', 'repo_B', 'repo_C') 
      AND path = 'Dockerfile';
    ```

### Step 3: FLARE Generation & Synthesis
**Goal:** The Agent synthesizes the final Dockerfile, pausing to query Coral if it hits a missing piece of knowledge.

1.  **Context Injection:** The LLM is provided the 3 real-world Dockerfiles fetched in Step 2.
2.  **Synthesis:** The LLM begins writing the final, modernized Dockerfile.
3.  **Active Retrieval (The FLARE Pause):** If the LLM identifies a legacy dependency (e.g., `torch==1.7.1+cu101`) and is unsure of the correct `--extra-index-url`, it triggers a tool call.
    * **Tool Call -> Coral SQL:** `SELECT content FROM github.issues WHERE repo = 'pytorch/pytorch' AND title LIKE '%1.7.1 cu101 install%' LIMIT 1;`
4.  **Resumption:** Coral returns the context, and the Agent finishes generating the optimized Dockerfile.

### Step 4: Verification Loop (Hadolint)
**Goal:** Ensure the generated syntax is valid before presenting to the user.

1.  **Action:** The backend runs the synthesized Dockerfile through `hadolint`.
2.  **Self-Correction:** If `hadolint` returns errors, the errors are fed back to the LLM for a final repair pass.

## 3. Technical Requirements

### Required Tooling
* **Agent Framework:** LangChain or custom Python orchestration script.
* **LLM Provider:** Groq (Llama-3-70B) or equivalent for fast tool-calling and code synthesis.
* **Data Retrieval:** Coral (running locally as an MCP Server).
* **Validation:** `hadolint` (installed locally on the backend).

### API Integration (Coral/MCP)
Ensure your Python backend implements an MCP Client capable of passing standard SQL syntax to the local Coral instance and receiving tabular data back.

## 4. Key Advantages for Hackathon Pitch
* **Zero Hardcoding:** Bypasses brittle python dictionaries mapping CUDA versions. The system adapts dynamically to any framework (JAX, TensorFlow, custom C++).
* **"Best Use of Coral":** Explicitly utilizes Coral's global search (`github.search_code` via predicate pushdown) and multi-step file extraction.
* **Advanced AI Architecture:** Implements state-of-the-art Agentic RAG (HyDE + FLARE) proving a deep understanding of LLM limitations and control flows.
